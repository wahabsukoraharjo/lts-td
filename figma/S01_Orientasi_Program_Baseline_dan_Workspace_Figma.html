FIG-S01 • Core Concepts

Definisi Program & Baseline

Makna setiap istilah dan cara menggunakannya dalam praktik

Slide 8

Program Magang Developer

Rangkaian pembelajaran terstruktur Agustus–November 2026 yang menggabungkan pengajaran, praktik, proyek, asesmen, logbook, dan bukti hasil belajar.

Kontrak Belajar

Kesepakatan mentor dan peserta mengenai target, jadwal, aturan komunikasi, mekanisme feedback, serta tanggung jawab penyelesaian evidence.

Baseline Assessment

Pengukuran kemampuan awal peserta sebelum materi dimulai. Hasilnya dipakai untuk menentukan dukungan dan prioritas latihan, bukan sebagai nilai akhir.

Learning Evidence

Artefak yang membuktikan proses dan hasil belajar, misalnya link Figma, screenshot, export, checklist, catatan test, atau changelog.

Definisi Workspace Figma

Makna setiap istilah dan cara menggunakannya dalam praktik

Slide 9

Workspace

Keseluruhan area kerja Figma yang mencakup toolbar, canvas, layers/assets panel, properties panel, pages, komentar, serta fitur kolaborasi.

Canvas

Area tak terbatas tempat frame, section, komponen, dan artefak desain disusun.

Toolbar

Kumpulan alat utama untuk memilih, membuat frame/shape, menulis teks, menggambar, memberi komentar, dan menjalankan prototype.

Properties Panel

Panel pengaturan visual dan perilaku objek terpilih, seperti ukuran, posisi, warna, typography, constraints, Auto Layout, dan prototype interaction.

Definisi operasional untuk praktik dan review

Definisi Struktur File

Makna setiap istilah dan cara menggunakannya dalam praktik

Slide 10

Page

Lapisan organisasi tingkat tinggi di dalam satu file Figma. Page membantu memisahkan latihan, komponen, wireframe, prototype, dan arsip.

Section

Area pengelompokan pada canvas untuk menandai fase, flow, atau kelompok layar.

Frame

Container utama yang memiliki ukuran, clipping, constraints, Auto Layout, layout grid, dan dapat menjadi screen prototype.

Layer

Setiap objek di dalam desain—teks, shape, image, frame, atau komponen—yang tersusun secara hierarkis di panel Layers.

Definisi Kolaborasi & Handoff

Makna setiap istilah dan cara menggunakannya dalam praktik

Slide 11

Comment

Catatan kontekstual yang ditempel pada area desain untuk diskusi, feedback, atau tindak lanjut.

Share Permission

Pengaturan siapa yang dapat melihat, berkomentar, atau mengedit file.

Export

Proses menghasilkan aset seperti PNG, JPG, SVG, atau PDF dari frame/objek.

Handoff

Proses menyerahkan desain kepada reviewer atau developer dengan struktur, state, ukuran, style, dan evidence yang cukup untuk dipahami.

Slide 13

FRAME

Container utama; mendukung ukuran, clipping, constraints, Auto Layout, dan prototype.

Gunakan: Gunakan untuk layar, region, atau komponen.

GROUP

Pengelompokan visual cepat tanpa kemampuan layout sekuat Frame.

Gunakan: Gunakan hanya untuk organisasi sementara.

Pengelompokan tingkat tinggi di canvas.

Gunakan: Gunakan untuk memisahkan flow, versi, atau area presentasi.

Apa Itu Portal Logbook Magang Developer?

Definisi proyek bulanan Figma

Slide 18
PORTAL LOGBOOK MAGANG DEVELOPER

Portal Logbook Magang Developer

Prototype antarmuka digital untuk mencatat aktivitas magang, pembelajaran, hambatan, solusi, bukti hasil kerja, feedback mentor, dan tindak lanjut pada setiap sesi.

Bentuk Deliverable

Pada bulan Figma, deliverable berupa prototype high-fidelity interaktif—bukan aplikasi produksi—yang menunjukkan struktur, alur, state, dan pengalaman pengguna.

Hubungan dengan Program

Prototype menjadi rancangan pengalaman yang dapat dijadikan acuan ketika fungsi serupa dikembangkan pada modul web Laravel, API Java Spring Boot, atau aplikasi Flutter.

Fitur & Alur Utama Project

Ruang lingkup minimum prototype

Slide 21
PORTAL LOGBOOK MAGANG DEVELOPER

Fitur Minimum

Dashboard progres, kalender sesi, form logbook, daftar evidence, feedback mentor, monitoring, asesmen, dan portfolio index.

Alur Peserta

Dashboard → pilih sesi → isi aktivitas/pembelajaran/blocker → lampirkan evidence → submit → lihat feedback → revisi atau selesai.

Alur Mentor

Monitoring → buka sesi/peserta → review logbook dan evidence → beri feedback/status → tetapkan next action.

Keberhasilan

Pengguna mampu menemukan sesi, mengisi logbook, menyerahkan evidence, menerima feedback, dan memahami status tindak lanjut tanpa kebingungan.

Dashboard→Pilih Sesi→Isi Logbook→Lampirkan Evidence→Review Mentor→Revisi / Selesai
