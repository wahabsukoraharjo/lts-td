FIG-S04 • Core Concepts

Definisi Component System

Makna setiap istilah dan cara menggunakannya dalam praktik

Slide 8

Component

Elemen utama reusable yang menyimpan struktur dan property dasar.

Instance

Salinan terhubung dari component yang mewarisi pembaruan dari component utama.

Override

Perubahan lokal pada instance, seperti teks, ikon, atau state, tanpa memutus hubungan dengan component utama.

Detach Instance

Memutus hubungan instance dari component; sebaiknya dihindari kecuali benar-benar diperlukan.

Definisi operasional untuk praktik dan review

Definisi Variants & Properties

Makna setiap istilah dan cara menggunakannya dalam praktik

Slide 9

Variant

Versi berbeda dari component yang dikelompokkan dalam satu component set.

Variant Property

Dimensi pembeda antarvariant, misalnya State, Size, Type, atau Theme.

Boolean Property

Property on/off untuk menampilkan atau menyembunyikan layer tertentu.

Text Property

Property yang memungkinkan teks instance diubah dari panel tanpa membuka layer.

Instance Swap

Property untuk mengganti nested component, misalnya ikon pada tombol.

Definisi operasional untuk praktik dan review

Definisi Styles & Tokens

Makna setiap istilah dan cara menggunakannya dalam praktik

Slide 10

Style

Nilai visual reusable untuk color, text, effect, atau grid.

Design Token

Nama semantik yang mewakili keputusan desain, misalnya color/status/success atau spacing/16.

Semantic Naming

Penamaan berdasarkan fungsi, bukan nilai visual, agar sistem mudah diubah dan dipahami.

Library

Kumpulan component dan style yang dipublikasikan agar dapat digunakan lintas file.

Definisi operasional untuk praktik dan review

Definisi Mini Design System

Makna setiap istilah dan cara menggunakannya dalam praktik

Slide 11

Mini Design System

Kumpulan prinsip, tokens, styles, components, states, dan dokumentasi minimum untuk menjaga konsistensi satu proyek.

Component Anatomy

Bagian pembentuk komponen, misalnya container, label, icon, helper text, dan state.

State

Kondisi komponen seperti default, hover, focus, disabled, error, atau success.

Usage Guideline

Aturan kapan komponen digunakan, kapan tidak digunakan, dan bagaimana mengisi kontennya.

Common Mistakes & Best Practice

Kesalahan yang perlu dihindari selama praktik

Slide 16
DON'T
  • Membuat komponen untuk elemen yang hanya dipakai sekali.
  • Menggabungkan terlalu banyak dimensi variant tanpa aturan.
  • Detach instance hanya karena ingin mengubah hal kecil.
DO
  • Mulai dari pola yang benar-benar berulang.
  • Gunakan property name yang jelas dan konsisten.
  • Dokumentasikan state, ukuran, penggunaan, dan larangan.
Review before submit

Troubleshooting Guide

Gejala, penyebab, dan tindakan perbaikan

Slide 17
GejalaPenyebab UmumSolusi
Variant sulit dicariNama property tidak konsistenGunakan pola State, Size, Type, Icon, dan Label.
Instance tidak dapat mengikuti updateTerlalu sering detach instanceGunakan override atau property sebelum detach.
Library tidak dipakaiKomponen tidak cocok dengan kebutuhan layarBangun berdasarkan pola nyata dari proyek, lalu refactor.

Hubungan dengan Program

Definition of Done

  • Minimal empat komponen reusable tersedia.
