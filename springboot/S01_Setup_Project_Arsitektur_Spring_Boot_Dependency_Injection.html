4 Pertanyaan Mental Model

Panduan mengambil keputusan implementasi

THINK • 09

1. Contract

Apa request, response, status, dan error yang dijanjikan kepada client?

2. Responsibility

Class atau layer mana yang seharusnya bertanggung jawab?

3. Failure & Security

Apa invalid input, not-found, unauthorized, dan failure scenario?

4. Evidence

Test, log, screenshot, atau dokumentasi apa yang membuktikan fitur bekerja?

Contract → responsibility → failure → evidence

Perbandingan Pendekatan

Memilih pola sesuai kebutuhan dan trade-off

COMPARE • 10

NEW MANUAL

Class membuat sendiri dependency dengan new.

Cepat untuk contoh kecil, tetapi coupling tinggi dan sulit diuji.

CONSTRUCTOR INJECTION

Dependency diberikan melalui constructor.

Pilihan utama untuk dependency wajib dan class immutable.

FIELD INJECTION

Dependency disuntik langsung ke field.

Ringkas, tetapi menyembunyikan dependency dan menyulitkan test.
Keputusan teknis harus memiliki alasan

Common Mistakes

Kesalahan yang perlu ditemukan sebelum code review final

DON'T • 21

Kesalahan Umum

  • Mencampur semua logic di controller.
  • Tidak memahami peran anotasi @SpringBootApplication.
  • Menghapus file build wrapper tanpa alasan.
  • Tidak mencatat dependency yang dipilih di README.

Cara Mencegah

  • Gunakan checklist sebelum commit.
  • Jalankan test dan baca log setiap perubahan penting.
  • Lakukan code review berdasarkan contract dan layer.
  • Catat limitation atau keputusan yang belum ideal.
Detect early, fix deliberately
