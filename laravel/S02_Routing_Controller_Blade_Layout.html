Best Practice

Kebiasaan yang menjaga kualitas implementasi

Slide 23
DO
  • Gunakan konvensi Laravel dan penamaan berbasis fungsi.
  • Pisahkan tanggung jawab route, controller, model, view, dan service sesuai kebutuhan.
  • Baca error/log dan uji perilaku setelah perubahan.
  • Buat commit kecil dengan pesan yang menjelaskan tujuan perubahan.
REVIEW LAYER
  • Apakah logic ditempatkan pada layer yang tepat?
  • Apakah input divalidasi dan akses dibatasi?
  • Apakah query dan response mudah dipahami?
  • Apakah evidence dapat dibuka mentor?
Quality is a repeatable habit

Common Mistakes

Kesalahan yang perlu dicegah pada sesi ini

Slide 24
DON'T
  • Menaruh semua logic di web.php
  • Tidak memakai route name
  • Duplikasi header/footer di tiap view
  • Tidak konsisten penamaan file view

Cara Melakukan Self-Review

  1. Jalankan ulang flow dari kondisi awal.
  2. Uji input valid, invalid, kosong, dan unauthorized.
  3. Periksa log dan database setelah aksi.
  4. Pastikan README/evidence diperbarui.
Prevent defects before mentor review

Troubleshooting Guide

Gejala, penyebab umum, dan langkah perbaikan

Slide 25
GejalaPenyebab UmumSolusi
Route not definedNama route salah atau belum didaftarkanPeriksa php artisan route:list dan konsistensi route name.
View not foundPath view tidak sesuai folder atau nama fileGunakan dot notation yang sesuai, misalnya tasks.index.
Menu menuju URL salahPath di-hardcodeGunakan route() dengan route name.
Layout terduplikasiSetiap view menyalin header/footerGunakan @extends, @section, component, atau include.
